Snowflake Bulk Ingestion
Framework

A metadata-driven data pipeline that loads files from Snowflake stages into target tables — with parallel execution, full audit logging, and clear extension points for CDC.

COPY INTO Dynamic task mapping Audit logging Error tracing CDC-ready
⚡

Parallel by default

Each table gets its own independent Airflow task. 50 tables run simultaneously — not sequentially.

🗂

Metadata-driven

Add a table by inserting one row into INGEST_CONFIG. Zero code changes required.

🔍

Debuggable

Three audit tables tell you exactly which file, line, and column caused a failure in seconds.

🔄

CDC extension points

MERGE and Stream CDC are already stubbed in SnowflakeLoader. Implement without touching the DAG.

Code walkthrough

DAG file — snowflake_bulk_ingestion.py

The DAG file is pure orchestration. It wires tasks together and calls helpers. No SQL, no result parsing — those live in the helper classes.

The full task pipeline

get_configs reads INGEST_CONFIG
→
validate_table dry-run COPY check × N tables
→
load_table runs COPY INTO × N tables
→
send_summary_email runs even on failure
PYTHONsnowflake_bulk_ingestion.py — wire-up
# The entire flow in 4 lines.
# .expand() creates one parallel task per table.
configs   = get_configs()
validated = validate_table.expand(config=configs)
loaded    = load_table.expand(config=validated)
loaded >> send_summary_email()

What each task does

TaskInputOutputJob
get_configs—List of dictsReads IS_ACTIVE=TRUE rows from INGEST_CONFIG, ordered by PRIORITY
validate_tableOne config dictSame dictDry-run COPY with VALIDATION_MODE=RETURN_ERRORS. Fails immediately on bad files.
load_tableOne config dict—Calls SnowflakeLoader, writes audit rows, saves per-file results
send_summary_email——Emails a status table for all tables. trigger_rule="all_done" — runs even if tasks failed.

Inside load_table — the 5 steps

PYTHONload_table task
run_id = str(uuid.uuid4())
# ↑ printed in Airflow task log — copy it to query audit tables

logger.start()              # 1. INSERT STARTED row into ETL_AUDIT

try:
    result = loader.load(config)       # 2. COPY INTO via SnowflakeLoader
    writer.write(run_id, result)       # 3. save per-file results
    logger.success(result.total_rows)  # 4. UPDATE ETL_AUDIT to SUCCESS

except Exception as exc:
    logger.failure(exc)               # 5a. write ETL_ERROR_LOG + mark FAILED
    raise                              # 5b. Airflow sees failure → retries
Helper class

AuditLogger — audit_logger.py

Owns every write to ETL_AUDIT and ETL_ERROR_LOG. The DAG task calls three methods and never writes audit SQL directly.

API — three methods

PYTHONaudit_logger.py
logger = AuditLogger(hook, run_id="abc-123", config=config)

logger.start()
# → INSERT INTO ETL_AUDIT ... STATUS='STARTED'
# Always call first — visible even if the process crashes mid-load

logger.success(rows_loaded=5000, files_loaded=3)
# → UPDATE ETL_AUDIT SET STATUS='SUCCESS', ROWS_LOADED=5000 ...

logger.failure(exc)
# → INSERT INTO ETL_ERROR_LOG (full traceback, error type)
# → UPDATE ETL_AUDIT SET STATUS='FAILED'
# Never raises — an audit write failure never hides the original error

ETL_AUDIT — column reference

ColumnSet byMeaning
RUN_IDstart()UUID printed in Airflow task log — use this for all debug queries
AIRFLOW_RUN_IDstart()Airflow dag_run_id — links to the Airflow UI
STATUSstart/success/failureSTARTED → SUCCESS or FAILED
DURATION_SECSauto (virtual column)Calculated automatically as END_TIME - START_TIME
ROWS_LOADEDsuccess()Total rows written across all files
FILES_LOADEDsuccess()Number of files with status=LOADED
ERROR_MESSAGEfailure()First 5000 chars of the exception message
Why insert STARTED before the load?

If the process is killed mid-run (OOM, network drop, server restart), the STARTED row remains visible in ETL_AUDIT. You know something was running — even without a FAILED status being written. Without this, a killed process is invisible.

Helper class

SnowflakeLoader — snowflake_loader.py

Owns all COPY INTO logic and result parsing. The load() method dispatches to the right private method based on load_mode. Adding CDC means adding a method here — nothing in the DAG changes.

The COPY INTO SQL it generates

SQLbuilt at runtime from config dict
COPY INTO PUBLIC.CUSTOMER
FROM   @RAW.CUSTOMER_STAGE
FILE_FORMAT          = (FORMAT_NAME = CSV_FORMAT)
PATTERN              = '.*\.csv'
MATCH_BY_COLUMN_NAME = CASE_INSENSITIVE   -- maps by column name, not position
ON_ERROR             = CONTINUE            -- skips bad files, doesn't abort the task
FORCE                = FALSE               -- skips already-loaded files (APPEND mode)

LoadResult — what the method returns

PYTHONLoadResult dataclass
result = loader.load(config)

result.total_rows_loaded    # int — total rows written to target table
result.total_files_loaded   # int — files with status LOADED
result.total_files_failed   # int — files with status LOAD_FAILED
result.had_file_errors      # bool — True if any file failed
result.file_results         # List[FileResult] — one per file in stage

# Each FileResult has:
fr.file_name    # "orders_2025-01-01.parquet"
fr.status       # "LOADED" | "LOAD_FAILED" | "PARTIALLY_LOADED"
fr.rows_loaded  # 5000
fr.errors_seen  # 0
fr.first_error  # "Field delimiter not found"
fr.error_line   # 42  ← line number in the file
fr.error_column # "CUSTOMER_ID"  ← which column rejected the value
ON_ERROR = CONTINUE explained:

If one file in the stage is unreadable, Snowflake skips it and loads the rest. The bad file appears in ETL_COPY_RESULTS with STATUS=LOAD_FAILED. The Airflow task still succeeds, but result.had_file_errors is True and a warning is logged. To make a bad file fail the task, change ON_ERROR to ABORT_STATEMENT.

Operations

Debug a failure

Follow these steps in order. You will find the root cause within 3 minutes. Open 02_debug_queries.sql in Snowsight — the queries are already there, ready to paste.

Find the RUN_ID first.

Every query below needs a RUN_ID. It's printed at the top of every Airflow task log: [load_table] START table=ORDERS run_id=f3a2b1c4-... — copy it.

Step 1

Which table failed?

SQL
SELECT TABLE_NAME, STATUS, START_TIME, DURATION_SECS, ERROR_MESSAGE
FROM   ETL_AUDIT
WHERE  STATUS = 'FAILED'
  AND  START_TIME >= DATEADD('hour', -24, CURRENT_TIMESTAMP())
ORDER BY START_TIME DESC;

Copy the RUN_ID from the result. Use it in all steps below.

Step 2

Which FILE caused it? (line + column)

SQL
SELECT FILE_NAME, STATUS, ERRORS_SEEN,
       FIRST_ERROR, FIRST_ERROR_LINE, ERROR_COLUMN_NAME
FROM   ETL_COPY_RESULTS
WHERE  RUN_ID = '<paste RUN_ID here>'
ORDER BY STATUS DESC;

This is the most useful query. It gives you the exact file, line number, and column name.

Step 3

Full Python traceback (if Steps 1–2 don't explain it)

SQL
SELECT ERROR_TYPE, ERROR_MESSAGE, STACK_TRACE
FROM   ETL_ERROR_LOG
WHERE  RUN_ID = '<paste RUN_ID here>';

Use this for connection errors, SQL syntax errors, or anything that happened before the COPY ran.

Step 4

Check what files are actually in the stage

SQL
LIST @RAW.CUSTOMER_STAGE;   -- replace with your stage name
Step 5

Preview errors without loading

SQL
COPY INTO PUBLIC.CUSTOMER
FROM   @RAW.CUSTOMER_STAGE
FILE_FORMAT     = (FORMAT_NAME = CSV_FORMAT)
VALIDATION_MODE = RETURN_ERRORS;  -- shows all errors, loads nothing

Fix the files in the stage, then re-trigger the DAG. Airflow will retry automatically up to 3 times.

Operations

Load modes

Set LOAD_MODE per table in INGEST_CONFIG. The DAG dispatches automatically — no code change needed.

Active now

APPEND

Adds new rows without touching existing data. Snowflake tracks which files it has already loaded and skips them automatically (FORCE=FALSE).

  • Safe to re-run — no double-loading
  • Best for fact tables and event logs
  • Daily incremental feeds
Active now

TRUNCATE_LOAD

Truncates the target table first, then loads all files. Uses FORCE=TRUE to override the file cache after truncation.

  • Full replacement each run
  • Best for small dimension tables
  • ⚠ Data is gone if load fails
Stub ready — implement in snowflake_loader.py

MERGE (CDC)

Upsert using MERGE INTO. Copy files to a staging table, then MERGE into target on specified keys — handles INSERT + UPDATE in one operation.

  • Handles late-arriving updates
  • Add MERGE_KEYS column to INGEST_CONFIG
  • Implement _merge_load()
Stub ready — implement in snowflake_loader.py

STREAM_CDC

Reads from a Snowflake Stream that captures INSERT / UPDATE / DELETE changes. Merges those changes into the target table.

  • Real-time change capture
  • Requires a Stream to be pre-created
  • Implement _stream_cdc_load()

The next scheduled DAG run loads this table. No code change, no DAG restart.

Adding CDC / MERGE

The extension point is already stubbed in snowflake_loader.py. You implement the method — the DAG routing works automatically.

1

Implement _merge_load() in snowflake_loader.py

PYTHONplugins/ingestion/snowflake_loader.py
def _merge_load(self, config: dict) -> LoadResult:
    staging    = f"STG_{config['table_name']}_{uuid.uuid4().hex[:8]}"
    merge_keys = config.get("merge_keys", "ID")

    # 1. COPY files into a temp staging table
    self._copy_to_staging(config, staging)

    # 2. MERGE staging into target on merge_keys
    self.hook.run(f"""
        MERGE INTO {config['target_schema']}.{config['table_name']} tgt
        USING {staging} src ON tgt.{merge_keys} = src.{merge_keys}
        WHEN MATCHED     THEN UPDATE SET ...
        WHEN NOT MATCHED THEN INSERT VALUES (...)
    """)

    # 3. Drop the staging table
    self.hook.run(f"DROP TABLE IF EXISTS {staging}")
    return LoadResult(...)
2

Add the dispatch line in load()

PYTHON
elif load_mode == "MERGE":
    return self._merge_load(config)
3

Update INGEST_CONFIG — done

SQL
-- Add merge_keys column (one-time migration)
ALTER TABLE INGEST_CONFIG ADD COLUMN MERGE_KEYS VARCHAR(500);

-- Enable MERGE for a specific table
UPDATE INGEST_CONFIG
SET    LOAD_MODE  = 'MERGE',
       MERGE_KEYS = 'CUSTOMER_ID'
WHERE  TABLE_NAME = 'CUSTOMER';

No DAG changes needed. The existing dispatch in load() routes it to _merge_load() automatically.
